# 小红书发布软件

本地 Web 工作台，负责：

- 递归扫描素材根目录，识别直接包含图片的发布文件夹，并保留年份 / 月份 / 相对层级信息。
- 自动选一组图片。
- 支持从 Finder 将不同文件夹中的图片逐张或多张拖入素材列表；每篇笔记最多发布 18 张图片，拼图封面和原图由用户决定是否同时保留。
- 左侧“自动发布”按账号保存独立计划：递归取组、随机选图、拼图、水印、成套文案、批量审核或全自动提交，并持续补充未来排期。
- Mac 异常提醒支持系统提示音、中文语音、自定义录音、单次播放 1–3 遍、指定次数或每 10 分钟 / 每小时重复，点击“已处理”停止。
- 生成 5 种小红书文案：夸赞型、专业展示型、过程分享型、观点讨论型、案例故事型。
- 将已确认的定时任务、账号 Profile、排期和执行状态保存到 SQLite，支持刷新和重启后恢复。
- 支持 DeepSeek 文案生成，失败时自动回落本地模板。
- 支持按当前 Chrome Profile 保存独立账号画像，可读取最近 20 条笔记并结合人工关键词生成画像。
- 支持超过 15MB 图片自动生成压缩副本。
- 调用 `tool-eval/xiaohongshu-skills` 自动填入小红书发布页。
- 定时发布兼容原生 `datetime-local` 和旧版文本控件，并在提交前校验页面实际保留的时间。

当前版本：`2026.11.10`。自动化测试覆盖目录扫描、SQLite 队列、发布状态确认、定时控件、账号画像和更新包校验。真实小红书页面测试记录单独保留在开发机，不随公开版本发布。

## 公开下载与更新

- GitHub 项目：[小红书发布软件](https://github.com/lengjueqi-coder/xiaohongshu-publisher)
- 首次安装：从 [Releases](https://github.com/lengjueqi-coder/xiaohongshu-publisher/releases/latest) 下载 `xhs-assistant-mac.zip`，解压后运行 `install.command`，再运行 `start.command`。
- 后续更新：软件启动时、前台每 10 分钟及重新回到软件时会检查新版本；顶部固定栏有文字按钮“检查更新”。发现 GitHub 正式新版本后，顶部显示更新提示。点击“一键更新并重启”后会验证 SHA-256、保留本机数据、替换应用文件并重启服务。
- 本仓库和 Release 是公开的，下载不需要 GitHub 账号。公开仓库不包含 `data/`、`config/`、API Key、SQLite 数据库、浏览器登录态、校准数据或发布素材。
- 每次发布新版本时，先同步更新 `app/server.py`、`start.command` 和本节版本号，提交并推送 `main`，再推送与软件版本一致的版本标签。GitHub Actions 会运行测试、构建 ZIP 与 SHA-256 文件并创建 Release。

安全边界：

- 不保存小红书账号密码。
- API Key 不再硬编码在源码中；可信设备之间复制 `data/assistant.sqlite3` 会携带本地已保存配置，因此不要把该文件发给不信任的人。
- “仅填入发布页”停在提交前；“立即发布”、审核确认或启用全自动计划会授权后台提交相应任务。
- 不绕过验证码、安全验证或平台风控。
- 不以随机点击或伪装保证“绕过”平台风控；软件采用账号级上限、串行提交、随机间隔、失败暂停和状态不明不重试等合规的风险控制。
- 无人值守提交前会读回图片数量、标题、正文、话题、原创、可见范围、定时和已要求的合集 / 地点 / @用户；不一致时暂停。新校验器仍需用真实平台账号完成验收，平台改版可能要求更新适配。
- 真实发布必须以小红书页面确认或管理页结果为准，CLI 返回成功本身不算平台已接收。

## 启动

双击：

```text
start.command
```

或命令行：

```bash
cd /你的解压路径/xhs-assistant
python3 app/server.py
```

新电脑首次使用请先运行 `install.command`，它会创建本地虚拟环境并按照 `requirements-mac.txt` 安装已验证的 Bridge 依赖。完整迁移与 Mac M 芯片安装步骤见：`安装教程-Mac-M芯片.md`。

打开：

```text
http://127.0.0.1:5818
```

如果更新文件后仍看到旧界面，先双击 `stop.command`，再运行 `start.command`。启动脚本会通过 `/api/version` 检查服务版本，避免把旧进程误当成新版本。

## 使用前准备

1. Chrome 扩展页保持 `XHS Bridge` 已启用。
2. Chrome 里保持小红书已登录。
3. 如果登录失效，在工作台点击“检测登录”，按提示扫码。

## 多账号与账号画像

- 右上角的全局账号入口显示两行：Chrome 用户资料名、小红书昵称，并优先使用小红书头像。入口独立于工作区分栏，拖动分栏或滚动页面不会将它挤出屏幕。
- 菜单中的“刷新当前账号资料”读取当前连接账号的昵称、头像，不会遍历或重启所有 Chrome 用户资料。其他账号显示上次识别的缓存；从未识别的显示“待识别”。在 Chrome 手动更换小红书账号后，请刷新资料。
- Chrome 用户资料隔离登录 Cookie；登录态仍由小红书决定是否过期，不能靠登录 Gmail 保证永久有效。每个运营账号请使用单独的 Chrome 用户资料。
- 左侧“行业热点”下方的“账号画像”打开独立设置页面，可填写账号关键词、长期话题、补充说明，并结合最近 20 条笔记生成画像。生成成功后自动按当前 Chrome 用户资料保存。尚未生成的输入只是本次打开期间的草稿。
- 切换到没有画像的账号时，输入框会清空；生成中的结果始终保存到发起生成时的账号。请避免在同一个 Chrome 用户资料内轮换运营账号，以免原画像不再适用。
